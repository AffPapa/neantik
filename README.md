# NeAntik — бесплатный антидетект браузер для Mac

NeAntik — открытый локальный антидетект браузер для Mac с Apple Silicon.
Нативный менеджер на SwiftUI запускает встроенный Chromium и хранит cookies,
настройки и данные сайтов отдельно для каждого профиля. Electron, отдельная
установка Chrome, обязательная учётная запись и продуктовая телеметрия не
нужны.

Это public-alpha для локального разделения браузерных сессий, приватности,
разработки и QA. NeAntik не обещает полную анонимность или необнаружимость и
не предназначен для обхода CAPTCHA, банов, антифрода или правил сайтов.

## Как пользоваться

1. Создайте профиль и задайте понятное имя.
2. При необходимости вставьте прокси; NeAntik распознает формат локально.
3. Нажмите «Запустить». Cookies и данные сайтов останутся только в этом
   профиле.

## Кому подходит NeAntik

- пользователям Mac с Apple Silicon, которым нужен бесплатный антидетект
  браузер без регистрации и облачной синхронизации;
- разработчикам и QA-инженерам, которым важно воспроизводимо разделять
  cookies, local storage, прокси и настройки браузерных профилей;
- тем, кто предпочитает локальное хранение профилей, открытый исходный код
  менеджера и проверяемый Direct Distribution release.

NeAntik работает только на macOS 14+ и Apple Silicon. Для Intel Mac, Windows,
Linux, командной работы, облачного запуска, RPA или API-автоматизации следует
выбрать другой продукт.

## Что умеет NeAntik

- хранит cookies, local storage и остальные данные в отдельных постоянных
  профилях;
- позволяет искать профили по имени и тегам, закреплять важные, убирать
  неактивные в архив и дублировать настройки в новый профиль с отдельными
  UUID, fingerprint seed и BrowserData; настройка прокси при этом тоже
  копируется;
- поддерживает Direct, HTTP/HTTPS с авторизацией через нативное окно Chromium
  и SOCKS5 без логина и пароля;
- умеет локально разобрать список прокси и создать до 100 отдельных профилей
  без автоматических сетевых запросов; при ошибке профили не сохраняются, а
  незавершённая очистка пароля помечается и повторяется при следующем запуске;
- хранит пароли прокси в Связке ключей macOS и не передаёт их в аргументах
  командной строки;
- запускает Chromium с минимальным allowlist системных переменных, не
  наследуя proxy-переменные, TLS key logs или токены из Terminal;
- не допускает повторный запуск одного профиля и корректно распознаёт живые
  helper-процессы;
- перемещает удаляемые данные профиля в Корзину, а секрет из Связки ключей
  очищает отдельным безопасным этапом;
- использует стабильный seed профиля для детерминированной изоляции
  браузерных поверхностей в совместимом Chromium runtime; новые профили
  равномерно распределяются системным CSPRNG между четырьмя проверенными
  Apple Silicon-когортами, а старые профили не ротируются;
- содержит защищённую release-only проверку A → B → A на стабильность и
  различимость профилей, не усложняя обычный пользовательский сценарий;
- не включает телеметрию в Direct-сборке.

## NeAntik и альтернативы: Vision, GoLogin, Dolphin, Multilogin, AdsPower и Octo Browser

NeAntik не является полной копией этих сервисов. Он отличается узкой моделью:
нативное локальное приложение только для Apple Silicon, без аккаунта, команды,
облачной синхронизации и автоматизации. Таблица помогает разобрать поисковый
запрос «аналог», но не заявляет равенство функций или объективное превосходство.

| Поисковый запрос | Официальный продукт | Главное отличие NeAntik |
| --- | --- | --- |
| Аналог Vision browser | [Vision Browser](https://browser.vision/ru/download) поддерживает несколько настольных ОС, аккаунты, команды и облачную синхронизацию | NeAntik — локальный Mac-only public-alpha без регистрации и командных функций |
| Аналог GoLogin browser | [GoLogin](https://gologin.com/pricing/) предлагает облачные запуски, тарифы, совместную работу и API в зависимости от плана | NeAntik не содержит облачных запусков, подписки, команды или REST API |
| Аналог Dolphin browser | [Dolphin {anty}](https://dolphin-anty.net/tarifs/) предлагает тарифы по числу профилей и пользователей | NeAntik бесплатен, но рассчитан только на одного локального пользователя Mac |
| Аналог Multilogin browser | [Multilogin](https://multilogin.com/pricing) объединяет браузерные профили, облачные телефоны, команды и API | NeAntik не эмулирует мобильные устройства и не предоставляет облачную платформу |
| Аналог AdsPower browser | [AdsPower](https://www.adspower.com/pricing) включает командные и automation-инструменты в зависимости от тарифа | NeAntik сознательно не включает RPA, синхронизатор и browser automation |
| Аналог Octo Browser browser | [Octo Browser](https://docs.octobrowser.net/en/payments/subscriptions/) использует подписки с разными лимитами профилей, команд и API | NeAntik не ограничивает локальные профили тарифом, но не предлагает команды и API |

Функции и тарифы сторонних продуктов меняются. Перед выбором проверяйте их на
официальных страницах по ссылкам в таблице.

## Вопросы и ответы

### Есть ли бесплатный антидетект браузер для Mac?

Да. NeAntik можно бесплатно скачать из GitHub Releases и использовать без
аккаунта на Mac с Apple Silicon и macOS 14+. Это public-alpha: перед рабочим
использованием прочитайте ограничения безопасности и проверьте совместимость
своего сценария.

### Как выбрать лучший антидетект браузер?

Лучший антидетект браузер нельзя определить одним рейтингом. Сравните
поддерживаемую ОС, изоляцию профилей, модель хранения данных, прокси, командные
функции, автоматизацию, стоимость, частоту обновления движка и прозрачность
проверки релизов. NeAntik подходит, если приоритет — локальный бесплатный
инструмент для Apple Silicon; для облака, команды, Windows/Linux или RPA нужны
другие решения.

### NeAntik — анонимный браузер?

Нет браузера, который сам по себе гарантирует полную анонимность. NeAntik
разделяет постоянные профили и поддерживает прокси, но сайт всё ещё может
учитывать аккаунт, IP, cookies, fingerprint, язык, поведение и другие сигналы.
Поэтому точнее называть NeAntik локальным браузером изолированных профилей, а
не гарантированно анонимным браузером.

### Что означает «бесплатный антик»?

Так часто сокращённо ищут бесплатный антидетект браузер. В случае NeAntik это
означает бесплатное приложение без обязательного аккаунта и платного тарифа,
но только для macOS 14+ на Apple Silicon и без облачной команды, RPA и API.

### Можно ли считать NeAntik заменой Vision, GoLogin, Dolphin, Multilogin, AdsPower или Octo Browser?

Только для части сценариев: локальных изолированных профилей на совместимом
Mac. Это не drop-in replacement облачных и командных функций перечисленных
сервисов. Сначала сравните свой сценарий с таблицей выше, затем скачайте
[текущий подписанный релиз](https://github.com/AffPapa/neantik/releases/tag/v0.3.23)
и проверьте его без переноса критичных рабочих данных.

## В опубликованном 0.3.22 (25)

Релиз `0.3.22 (25)` прошёл Direct Distribution gate и опубликован как
immutable GitHub Release. Он делает список главным рабочим экраном:
адаптивная строка объединяет выбор, запуск, профиль, статус, подключение и
контекст, а полная карточка открывается в необязательном inspector. Явный
множественный выбор поддерживает атомарное закрепление, перемещение, теги и
архив с безопасной отменой последнего действия.

Локальный поиск понимает операторы `тег:`, `папка:`, `прокси:` и `статус:`.
Массовый импорт читает вставленный текст или ограниченный TXT/CSV-файл без
перехода по symlink и без автоматических сетевых запросов. Размер BrowserData
измеряется только по запросу в карточке профиля, поэтому список остаётся
быстрым.

Также входят поэтапный launch preflight, полоса активных профилей, отдельное
подтверждение Force Stop, редактирование «на следующий запуск», «Создать
похожий», повтор только ошибочных proxy-check, «Центр готовности» и
детерминированные бюджеты скорости, памяти, размера исходников и приложения.
Исследование и текущая карта продукта записаны в
[Project map](docs/PROJECT_MAP.md).

Следующие изменения входят в опубликованный подписанный и нотарифицированный
релиз:

- пустой workspace предлагает «Создать и открыть»: NeAntik атомарно создаёт

- одноуровневые папки, перенос профилей между ними и создание/импорт сразу в
  выбранную папку; быстрый список переноса ограничен восемью вариантами, а
  остальные доступны через поиск; legacy `profiles.json` при этом не меняет
  формат;
- одно главное окно macOS и единое состояние команд профиля для toolbar,
  контекстного и системного меню; во время sheet/alert команды блокируются и
  не могут перезаписать несохранённый черновик;
- стабильные системные цвета тегов как дополнительный ориентир в sidebar,
  строке и редакторе; название тега остаётся главным сигналом, а цвета
  ошибок и готовности не переиспользуются;
- простая необязательная локальная заметка профиля: полноширинная строка
  редактора раскрывает обычное многострочное поле, выбранный профиль
  показывает текст по запросу, компактный список сохраняет только значок, а
  общий поиск находит текст заметки; клон начинает с пустой заметки. Заметки
  не хранятся в Связке ключей или облаке, не поддерживают rich text и не
  входят в будущий публичный DTO;
- массовое создание профилей начинается со вставки списка прокси: локальный
  предпросмотр сохраняет корректные строки, показывает номера всех ошибок и
  раскрывает тип, порядок полей, имя и папку только по запросу; сеть при
  вставке не используется, а создание остаётся атомарным;
- одиночная и массовая добровольная проверка прокси, не более трёх проверок
  одновременно, с временем, результатом и безопасной локальной историей без
  точного IP;
- свежая автоматическая подготовка перед каждой сессией прокси-профиля:
  нажатие «Запустить» заново проверяет текущий маршрут и только затем запускает
  браузер с согласованными часовым поясом и языком. Ручная проверка остаётся
  диагностикой и не заменяет эту подготовку; прямые профили внешний запрос не
  выполняют, а ошибка прокси не вызывает скрытый переход в Direct;
- экран «Среда профиля» для fingerprint, WebRTC, QUIC/DNS, маршрута и
  геолокации с честным разделением настроек и реально измеренных фактов;
  необязательные ещё не запущенные проверки не считаются предупреждениями,
  одинаковая причина не дублируется, а реальная проблема ведёт к одному
  понятному действию или исправляется автоматически перед запуском;
- обычный локальный запуск A → B → A-проверки fingerprint, который не создаёт
  release evidence;
- единый immutable workspace snapshot и allowlisted read-only DTO как основа
  будущих UI/API/MCP/SDK-адаптеров. Сетевой listener и write-методы сейчас не
  реализованы и автоматически не включаются.

Для HTTP/HTTPS-прокси с авторизацией отдельные кнопки копируют логин и пароль
в нативное окно Chromium. Пароль остаётся в Связке ключей и никогда не попадает
в browser CLI. Скопированное значение помечается как временное и очищается
через 60 секунд, если буфер не был изменён; в течение этого времени другие
приложения с доступом к буферу всё ещё могут его прочитать.

## Границы безопасности

NeAntik предназначен для приватности, разделения рабочих сессий, разработки и
QA. Он не обещает полную анонимность или «необнаружимость» и не предназначен
для обхода CAPTCHA, банов, антифрода или правил сторонних сервисов.

Версия `0.3.23` опубликована для public-alpha изоляции профилей. Строгая
production-согласованность всех fingerprint- и сетевых поверхностей остаётся
открытым ограничением.

Встроенный privacy-oriented Chromium собирается без Google Safe Browsing.
NeAntik не отправляет историю посещений в Google, но и не заменяет отдельную
защиту от фишинга, вредоносных сайтов и опасных загрузок. Не открывайте
недоверенные ссылки только потому, что они запущены в изолированном профиле.

Четыре когорты — проверенная продуктовая политика, а не статистика рынка и не
гарантия анонимности. Стабильный отпечаток одного профиля по назначению
связывает его повторные посещения; cookies, аккаунты, прокси, язык, поведение и
другие сигналы тоже могут связывать сессии. Сейчас политика уменьшает набор
аппаратных конфигураций, но не объединяет Canvas, Audio, WebGL и ClientRects
разных пользователей в общий отпечаток.

Каждый бинарный релиз проходит GUI-проверку A → B → A, Developer ID,
notarization, stapling, Gatekeeper и повторную проверку скачанного артефакта.
Подпись fingerprint evidence выполняется на физическом Secure Enclave точного
Developer ID-кандидата без software fallback. Подробности:
[fingerprint evidence schema 8](docs/security/fingerprint-evidence-schema-8.md).

Уязвимости следует сообщать по правилам [SECURITY.md](SECURITY.md).

## Структура репозитория

- `Sources/NeAntik` — нативный SwiftUI-менеджер;
- `Tests/NeAntikTests` — тесты менеджера, профилей, прокси и приватности;
- `runtime` — source locks, manifest патчей и лицензии Chromium;
- `scripts` — сборка, проверки, подпись и Direct release gates;
- `docs` — архитектура, приватность, runtime и выпуск;
- `releases` — метаданные и checksums публичных бинарников, но не сами
  бинарники.

Многогигабайтный Chromium checkout, build cache, `.app`, ZIP и DMG намеренно
не хранятся в Git. Runtime воспроизводится из зафиксированных upstream
исходников и открытого набора патчей. Подробнее:
[сборка из исходников](docs/BUILDING.md),
[Direct distribution](docs/DISTRIBUTION.md) и
[граница supply chain](docs/RUNTIME_SUPPLY_CHAIN.md). Текущие приоритеты и
сознательно исключённые функции перечислены в
[дорожной карте](docs/ROADMAP.md).

## Сборка менеджера

Понадобятся Mac с Apple Silicon, macOS 14+ и Xcode 26+.

```bash
./scripts/verify-native-swift-tests.sh
./Develop-NeAntik.command
```

`Develop-NeAntik.command` — быстрый цикл для интерфейса и Swift-кода. Он один
раз создаёт APFS-клон встроенного Chromium, затем пересобирает только менеджер
и открывает отдельную `NeAntik Dev.app`. У неё отдельные профили
(`NeAntik Development`) и отдельное хранилище паролей; `dist`, notarization,
GitHub и сайт не изменяются. Перед запуском команда глубоко проверяет Chromium
и при необходимости восстанавливает только dev-копию локальной ad-hoc
подписью — без Developer ID и нотариализации. Для проверки без открытия окна:
`./Develop-NeAntik.command --no-open`.

`Release-NeAntik.command` запускайте только для окончательного точного
кандидата: этот путь включает тяжёлые release-gates, проверку A → B → A,
Developer ID, Apple notarization и создание ZIP/DMG.

Полная Direct-сборка дополнительно требует подготовленный Chromium runtime.
Сертификат Developer ID и данные notarization остаются только в Связке ключей
владельца релиза и не хранятся в репозитории или GitHub Actions.
Для защищённого Keychain/Secure Enclave enrollment также нужен внешний
Developer ID distribution provisioning profile, который разрешает Keychain
Sharing для точного App ID `app.neantik.desktop`. Файл профиля тоже не
коммитится: перед запуском задайте его абсолютный путь, например
`NEANTIK_PROVISIONING_PROFILE=/absolute/path/to/NeAntik.provisionprofile`.
Release gate проверяет CMS-подпись Apple, срок действия, Team ID, App ID,
distribution-тип, embedded profile и итоговые entitlements подписанного app.

Выпуск идёт в два этапа: сначала создаётся и подписывается один точный
`NeAntik.app` с неизменяемым manifest всего bundle, затем свежая GUI-проверка
A → B → A привязывается к этому кандидату. Этап notarization один раз
упаковывает live app в приватный ZIP, проверяет и отправляет Apple именно эти
байты, извлекает из принятого ZIP отдельный staged app и stapler работает
только с ним. Финальные ZIP и SHA публикуются без перезаписи, ZIP — последним
commit point. Канал `public-alpha` и строгий `production` выбираются явно и не
подменяют друг друга.

`productionQualified` означает строгую согласованность fingerprint и
WebRTC-контроль для настроенного маршрута. Он не утверждает, что фактический
HTTP/DNS-выход был измерен: verifier явно возвращает
`effectiveHTTPRouteObserved=false`.

## Проверки

Основные локальные gates:

```bash
./scripts/verify-native-swift-tests.sh
python3 scripts/verify-public-fingerprint-corpus.py
python3 scripts/verify-open-source-tree.py
python3 scripts/verify-public-workflow-references.py
```

Проверка точных исходников Chromium 152 и source-qualified candidate:

```bash
python3 scripts/verify-runtime-source-provenance.py \
  /absolute/path/to/source-provenance.json \
  --source-root /absolute/path/to/chromium/src
python3 scripts/verify-runtime-candidate-lock.py \
  /absolute/path/to/runtime-candidate-lock.json \
  /absolute/path/to/source-provenance.json
```

Source contract для `152.0.7977.64` не подтверждает готовый бинарник сам по
себе. Promotion в release lock разрешён только после новой Metal-сборки и
точного schema-3 runtime verification report.

GUI evidence проверяется отдельно:

```bash
python3 scripts/verify-gui-fingerprint-report.py \
  /absolute/path/to/fingerprint-audit.json \
  --require-production
```

Диагностический или headless-отчёт не может пройти production gate. Нужен
обычный GUI-запуск с доступными и стабильными Canvas, WebGL pixels, Audio,
ClientRects, GPU metadata и Client Hints.

## Локальные данные

Профили и browser data:

```text
~/Library/Application Support/NeAntik/
```

Пароли прокси хранятся отдельно в Связке ключей macOS. Локальные fingerprint
отчёты находятся в:

```text
~/Library/Application Support/NeAntik/FingerprintAudits/
```

Отчёты имеют приватные права доступа. Публичный handoff может содержать только
агрегированную аттестацию без имён и ID профилей, seed, адресов прокси и
browser-surface значений.

## Участие в разработке

Перед pull request прочитайте [CONTRIBUTING.md](CONTRIBUTING.md). Синтетический
[fingerprint conformance corpus](docs/PUBLIC_FINGERPRINT_CONFORMANCE.md)
позволяет проверять release verifier без публикации реальных профилей,
fingerprint seed или proxy-конфигурации.
Контракт разрабатываемой аутентифицированной оболочки и её честные ограничения
описаны в
[документе schema 8](docs/security/fingerprint-evidence-schema-8.md).

Исходники NeAntik распространяются по MPL-2.0. Производные файлы Chromium
сохраняют свои upstream-лицензии и notices. Название и логотип регулируются
[TRADEMARKS.md](TRADEMARKS.md).

## Проверка выпуска и отдельная публикация сайта

Проверить локальные Direct Distribution tools, GitHub-доступ и структуру
последнего immutable GitHub Release одной командой:

```bash
./scripts/neantik-affpapa-release doctor
```

Эта команда не требует server key и не меняет сайт. Если публикация сайта
явно авторизована, отдельно проверяют restricted channel и публикуют уже
подготовленный release-каталог:

```bash
./scripts/neantik-affpapa-release site-doctor
./scripts/neantik-affpapa-release publish /absolute/path/to/release-dir
```

Ручные SSH/SCP/SFTP для этого не нужны и запрещены серверным forced-command.
Полный контракт: [ops/affpapa/README.md](ops/affpapa/README.md).
