# Обновление NeAntik: интерфейс и границы

Статус: опубликована **0.9.3 (203), public alpha**. Доказательства опубликованного выпуска находятся в [release record](../releases/v0.9.3.json). Следующий выпуск пока не опубликован. Проверка канала, загрузка ZIP, проверка кандидата и установка — отдельные стадии; скачивание не разрешает установку.

## Важное ограничение публичной0.9.2

Проверка настоящего кандидата выявила отказ `signature.policy`: старый установщик ошибочно требует флаг Hardened Runtime у Chromium framework dylib. Его штатная подпись имеет flags0; подписи приложения и исполняемого runtime проходят проверку. Переподпись библиотеки не решает обновление старого клиента, поскольку он также закрепляет точные хеши runtime.

Для 0.9.2 требуется ручная установка нотариализованной 0.9.3 из GitHub Releases после полного выхода из NeAntik. Не удаляйте каталог данных профилей. Исправление нового установщика принимает обычную подпись библиотеки, сохраняя обязательный Hardened Runtime исполняемых приложений и все остальные проверки. Скачивайте только существующие опубликованные файлы.

Проверка новых shipping helpers на подписанном synthetic202 carrier — самостоятельная проверка компонентов; она не считается успешным обновлением старого публичного202.

## Как обновиться

1. Закрой браузерные окна и дождись завершения операций с профилями.
2. Нажми **Обновить NeAntik… → Проверить обновления**. Подпись описания и срок действия проверяются до показа новой версии.
3. По подписанному описанию можно загрузить ограниченный по размеру ZIP внутри приложения или выбрать оригинальный ZIP вручную. Сверяются его SHA-256 и допустимый runtime; неизвестный движок не становится доверенным из manifest. [GitHub Releases](https://github.com/AffPapa/neantik/releases/latest) остаётся ручным источником архивов.
4. После проверки файлов появится **Установить и перезапустить**. Нажатие разрешает установку; новый процесс должен подтвердить запуск. При отказе до подтверждения установщик возвращает прежнее приложение.

Вместо проверки канала можно выбрать ZIP и подписанный JSON manifest того же выпуска вручную. DMG и обычный файл SHA-256 не заменяют эти входы. Ручная установка DMG/ZIP в «Программы» также остаётся доступной. Данные профилей удалять не нужно; предыдущие release assets сохраняются.

## Границы проверки

Проверяются подпись Ed25519, срок описания, возрастающий build, macOS/architecture, hash ZIP, безопасная распаковка, Developer ID, runtime provenance, notarization и bootstrap. Название файла или успешное скачивание сами по себе ничего не подтверждают. При ошибке выбери оригинальные файлы выпуска и закрой другой менеджер.

Канал берётся из подписи установленного приложения. HTTPS retrieval ограничен разрешёнными адресами, 128 KiB и timeout; cookies, сохранённые сетевые пароли и кэш не используются. Подписанная0.9.2 использует `/api/update-v2.json`: это действующий канал со схемой manifest1 и новым helper continuity, не отдельный формат manifest. `/api/update.json` — прежний маршрут. Наличие подписанного latest не доказывает возможность пропуска любых промежуточных версий: пакет переносит одну предыдущую primary-пару helpers. Соседний переход требует native install/rollback; для более старого клиента остаётся ручная установка оригинального DMG/ZIP с сохранением данных.

Контроллер принадлежит приложению, держит admission fence до настоящего завершения операции и отмены. Закрытие sheet не означает завершение worker. При неизвестном результате cleanup требуется штатный выход. Согласие и исчезновение старого процесса не равны успешной установке: результат подтверждается commit/ACK и новой версией.

Исторический native gate 0.8.10→0.8.11 использовал два синтетических metadata-only профиля и mock Keychain; он не доказывает работу текущей пары версий, перенос паролей между Mac, долговечность свежих cookies или поддержку каждой версии macOS. Смена helper/runtime/media permissions требует новой квалификации. Сохранение подписанной предыдущей primary-пары описано в [workflow](DEVELOPMENT_WORKFLOW.md); изоляция QA — в [контракте](DIRECT_UPDATE_AUDIT_ISOLATION.md).
