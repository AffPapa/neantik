# Определение типа прокси

Опубликовано в [0.8.23 (135), public alpha](../releases/v0.8.23.json).
[Отдельное доказательство точного кандидата](evidence/proxy-protocol-discovery-0.8.23.json); полный source/Dev набор остаётся историческим отчётом.

В редакторе Chromium-профиля кнопка **«Определить тип без пароля»** обращается
только к введённому адресу и порту. Вставка и разбор строки не запускают сеть.
Детектор принимает `ProxyProtocolEndpoint`: только host/port, без конфигурации
профиля, Keychain и учётных данных.

1. Отправляется SOCKS5 greeting с методами no-auth и username/password.
   Само сообщение авторизации не отправляется. Ответы 0, 2 и 255 подтверждают
   только протокол, в том числе отказ по методам.
2. При неопределённом результате отдельное TCP-соединение отправляет HTTP
   CONNECT на зарезервированное имя `neantik-protocol-probe.invalid`.
   Нет Authorization, запроса IP/GeoIP или настоящего сайта. HTTP признаётся
   только по корректному 407 с Proxy-Authenticate. Обычный HTTP200, даже с
   текстом Connection Established, недостаточен.
3. Результат применяется явно. Редактирование полей, смена режима и закрытие
   редактора отменяют задачу и сбрасывают результат. UUID запроса и endpoint
   исключают принятие старого ответа после A→B→A.

Общий срок — четыре секунды, ответ ограничен 4096 байтами. Cancellation и
завершение закрывают транспорт. Проверка пароля, доступности и фактического
маршрута браузера выполняется отдельно; зелёный network status не создаётся.

## Ограничения

HTTPS upstream не определяется этой пробой. HTTP без однозначного auth
challenge может остаться неизвестным. Пользователь выбирает тип вручную;
ничего не угадывается по порту. MCP-контракт и WebKit proxy policy не меняются.

## Проверка

`ProxyProtocolDetectorTests` проверяет грамматику, пределы и устаревшие ответы.
`ProxyProtocolSocketTests` использует собственные реальные loopback-соединения:
SOCKS5 с/без авторизации, fragmented ответы, HTTP407, HTTP200 negative,
повреждённый/слишком большой ответ, timeout и cancellation. Снимки peer
подтверждают точные публичные байты пробы и клиентское закрытие до принудительной
очистки fixture. Это не заменяет Dev UI и точный подписанный кандидат.

[Результаты исходных и оконных проверок](evidence/proxy-protocol-discovery-development.json)
сохраняют отдельно провалы aggregate benchmark, его изолированный PASS и
остановленный полный Python-прогон. Связанные Python-контракты выбраны по
проверенной карте читателей исходников; runtime/release gates не ослаблены.
