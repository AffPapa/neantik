# Подпись описания обновления

Это служебный инструмент выпуска, не установщик и не подтверждение нотарификации.
Developer ID подписывает приложение прежним сертификатом. Отдельный Ed25519-ключ
подписывает JSON с версией, сроком действия и SHA-256 исходного ZIP. В приложение
и Git попадают только идентификатор и публичная часть этого ключа.

## Порядок выпуска

1. Пройти текущий Direct doctor: provenance, точный кандидат, fingerprint evidence,
   Developer ID, notarization, stapling, Gatekeeper и проверка ZIP/DMG.
2. Подготовить payload по контракту `UpdateManifestPayload`. Указать фактические
   version/build/Chromium, имя исходного notarized ZIP, его SHA-256 и точную ссылку
   `https://github.com/AffPapa/neantik/releases/download/vVERSION/NeAntik-VERSION-arm64-notarized.zip`.
   Использовать UTC даты без дробных секунд; срок действия не более 14 дней.
3. Подписать JSON ниже. Утилита проверяет контракт, локальные байты ZIP и текущую
   закреплённую security baseline. Она не обращается в сеть и не оценивает подпись
   приложения; шаг 1 остаётся обязательным.
4. Публиковать feed только для реально опубликованного архива после проверки
   публичных байтов. Новый feed не заменяет старые неизменяемые release assets.
5. Проверить получение по HTTPS настоящим установленным кандидатом. При истечении
   срока подписать новое описание тех же проверенных публичных байтов; ключ остаётся
   прежним. Истёкшее описание должно отклоняться, без обхода проверки срока.

## Хранение ключа

Каталог ключа — вне Git, абсолютный путь без symlinks, владелец текущий пользователь,
права 0700. Файл — 0600, regular file, без hardlinks. Ключ не передаётся в argv,
журналы, сайт или CI. Оператор отвечает за защищённую резервную копию ключа.
Новая генерация никогда не перезаписывает существующий файл.

```sh
python3 -B scripts/direct-update-signing.py --openssl /opt/homebrew/opt/openssl@3/bin/openssl \
  generate-key --key /ABSOLUTE_PRIVATE_DIRECTORY/release-ed25519.pem

python3 -B scripts/direct-update-signing.py --openssl /opt/homebrew/opt/openssl@3/bin/openssl \
  sign --payload /ABSOLUTE_RELEASE_DIRECTORY/update-payload.json \
  --archive /ABSOLUTE_RELEASE_DIRECTORY/NeAntik-VERSION-arm64-notarized.zip \
  --key /ABSOLUTE_PRIVATE_DIRECTORY/release-ed25519.pem \
  --key-id neantik-direct-20261012-v1 \
  --output /ABSOLUTE_RELEASE_DIRECTORY/update.json
```

Вывод команды содержит только публичный ключ, его ID и hash envelope. Существующий
output не перезаписывается. При ошибке записи неполный новый файл сохраняется для
диагностики; его нельзя публиковать. Перед публикацией проверить полный envelope
верификатором приложения и сравнить его hash с результатом команды.

Локальные тесты используют одноразовые ключи и явно синтетический архив: настоящая
подпись, независимая OpenSSL verification, подмена payload/ZIP, неверный алгоритм,
symlink/FIFO/hardlink, права, срок, baseline и запрет перезаписи. Эти тесты не
подтверждают установку приложения или доступность production feed.

## Происхождение движка и дата релиза

Неизменяемые исходные доказательства Chromium проверяются по закреплённому
полному хешу дерева. `release-security-baseline.json` содержит отдельную дату
проверки публикации, поэтому не входит в исторический хеш. Его точные байты
остаются защищены подписью приложения и проверкой неизменности распакованного
кандидата. Updater проверяет формат, официальный источник, даты и минимальную
версию Chromium. Свежесть наблюдения на день публикации проверяет Direct doctor;
при установке уже опубликованного выпуска updater не требует сегодняшнюю дату.
Упаковка дополнительно сверяет фактический кандидат с compiled runtime pins.
