# NeAntik Chromium + WebKit implementation plan

Base: published source `8ceaf9077f9b77dff885ea866e8fb101dfa93056`. Work in a separate development checkout with new synthetic profile IDs. The published 0.9.6 artifacts, rollback and existing profile data are fixed inputs. Record actual evidence in CURRENT and dated receipts.

## Architecture

- The manager owns profile metadata, identity settings, revision, leases and a route policy. Chromium retains its existing bundled runtime and controls. WebKit chooses between macOS WebKit for explicit Direct profiles and the signed owned host for profiles that require an isolated proxy. The manager rejects any unsupported combination before acquiring a lease, resolving credentials or starting a view. No runtime or storage fallback.
- The system-WebKit path uses the persistent UUID store and the native OS identity. Keep the existing store IDs. Keep the owned profile's store and process identity separate. Restart or failure must preserve explicit engine, route and revision. Capabilities reported by GUI and MCP describe support separately from an observed live route.
- The owned WebKit host verifies its exact loaded runtime, profile lease handoff and Networking XPC identity. Its outgoing network boundary permits only the profile's authorized broker. The broker owns upstream TLS/CONNECT or SOCKS5, name resolution policy, revocation and upstream credentials. Losing the attested Networking owner revokes the exact route and requests a graceful save and close of that profile generation. A new launch requires a fresh lease. Check the boundary at the Networking process, not just in WKWebsiteDataStore.
- Support explicit WebRTC policies. A system Direct profile retains its native WebRTC policy unless the user requests blocking. A proxied owned profile blocks peer connections unless the signed private relay scope is active. Native disable must close peer connections and data-channel APIs before the first page, or refuse the protected launch. Media permission is separate. Relay-only may be added only after a real controlled TURN session proves the advertised candidate and traffic route match and no direct UDP path survives. Do not fake candidate IP strings. Never apply Chromium fingerprint injection to WebKit.
- Qualify each proposed WebKit identity parameter independently. Start with native coherent WebKit identity; offer an override only if the engine can apply it consistently to HTTP, documents, frames and workers as applicable, and A→B→A proves persistence and separation. Preserve unavailable settings and expose the reason. Avoid claiming anonymity or indistinguishability.

System WKWebView's historical proxy negative sent Direct traffic to a reachable private-IP canary with failover disabled. A successful named CONNECT on an unreachable-by-Direct domain is not a substitute. The earlier isolated V4 IPC EOF occurred before any observed DNS or origin traffic. Retained owned-runtime HTTP, TLS and UDP4 evidence applies to those development bytes; missing temporary paths and incomplete recipient/release gates remain open. See `WEBKIT_PROXY_QUALIFICATION.md`, `NEXT_1_0_SLICES.md` and the exact referenced receipts.

The [Chromium headless loopback control](../scripts/runtime-network/run-chromium-headless-loopback.py) uses the public ZIP and two disposable browser data directories. It checks a serial A → B → A sequence against independent local HTTP proxies, verifies storage restoration and requires process exit between runs. It supplements Chromium's headed manager qualification. An admission refusal preserves the extraction for `--resume`, which rechecks the archive binding and signed identity before a new eligible attempt.

## WebRTC transport acceptance

1. Prove the local fixture first with an enabled control. The [loopback TURN fixture](../Experiments/OwnedWebKitNetworkBoundary/turn-fixture/README.md) verifies authentication, independent relay allocations and delivery of a nonce at the TURN data plane. In the browser, count authenticated TURN allocations and verify a relay candidate and DataChannel nonce separately. Restrict all listeners and canaries to synthetic loopback endpoints.
2. For WebKit Off, verify native rejection before page creation, then probe the API in the main document, a frame and a new window, including after a profile restart. Require zero forbidden STUN, TURN and DNS traffic in the same run. Report media permission separately.
3. For WebKit Relay-only, enforce an immutable profile policy in both PeerConnection creation and `setConfiguration`. At `NetworkRTCProvider`, reject direct resolution, UDP and unbound sockets before creation. Bind eligible TURN TCP/TLS to the same `NetworkSessionCocoa` proxy capability as the owned store with failover disabled. Reject TLS failures and revoke active sockets with the broker lease. ICE candidate filtering alone does not enforce this transport boundary.
4. Require a relay candidate and a delivered nonce through the selected broker, with zero direct canary hits. Try a page override to `all`, unapproved STUN/TURN, IPv4 and IPv6, broker failure, cross-profile routes, and revocation and recovery. Keep Relay-only unavailable until those cases pass on one signed candidate.

### Owned WebKit relay policy and regression phases

The [WebCore policy patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-relay-policy.patch) applies to owned source commit `6bb8be95e06ac242424d8eb53cdd6b9a81cb55e5`. Its preference defaults off. The owned host can enable it after the Networking session enforces mandatory proxy routing for RTC and denies forbidden transports. The patch is staged separately from the current baseline build.

- Fix the relay policy before the owned data store creates its first Networking process. Carry it with the session parameters when recreating that process. Bind RTC socket admission to the trusted NetworkProcess session ID and that session's mandatory proxy configuration. Missing session policy or proxy capability fails closed.
- Normalize the effective ICE policy in the PeerConnection constructor and setter before ICE server validation. `getConfiguration()` must expose the effective relay policy. Reject direct ICE DNS, UDP, mDNS, and interface probes while preserving completion for rejected requests. For approved TURN TCP/TLS hostnames, preserve the hostname for the mandatory proxy so that routing does not depend on a direct DNS result.
- Run the existing Off A and Relay B positive control first. For a new TURN matrix, use `--peer-control --own-peer-stun` so the controller verifies a UDP4 loopback canary before the browser and requires one top/iframe API report and zero direct STUN packets in every phase. The monitor continues through fixture teardown. The combined private candidate can run trusted click and Metal in A1, then positive TURN/TLS, outage, Networking replacement and return to A in the same manager run. Keep the wrong-host and missing-intermediate cases separately scoped to their sealed fixtures. A missing, timed-out or duplicate report does not qualify the phase. Previously sealed fixtures with an external STUN observer retain their original scope. In separate B phases preserve the same approved TURN servers and attempt both explicit `iceTransportPolicy: 'all'` and omission of `iceTransportPolicy` through `setConfiguration()`. Require relay configuration, relay candidates, a working DataChannel nonce after ICE restart, the expected broker counts, and zero direct canary hits. Use the broker transport count or selected candidate `relayProtocol` for the browser-to-TURN hop. A TURN relay candidate can describe UDP on the server side while the browser connects by TCP/TLS.
- After the fixture records B2, use `scripts/runtime-network/restart-owned-webkit-networking.py --run-plan <run-plan.json>` to signal the exact candidate’s attested Networking child and verify its exit. Close the profile normally before arming B3, then reopen the same profile and repeat the positive route with fresh counter baselines. In a separate phase cut its proxy while the direct TURN canary remains reachable. Require no direct hit and no delivered nonce. Cover hostname DNS and mDNS with their own canary or explicit denial counters before claiming hostname coverage.
- Apply the [TURN/TLS trust patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-relay-turn-tls.patch) after the relay patches. The relay-only socket preserves Network.framework's server trust policy and disables fetching missing intermediate certificates. Apply the [configuration block lifetime patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-relay-turn-tls-block-lifetime.patch) to the production source layout after its existing QA patch series. Compile production with both QA CMake options disabled. The private diagnostic layout instead uses the [block lifetime and trust diagnostics patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-turn-tls-block-ownership.patch) after its peer authentication patch. The local TURN fixture has an opt-in TLS listener. Its Go and Python wire controls exercise the server and CONNECT transport. The browser A/B/A controller uses plain TURN by default and supports the private TURN/TLS fixture. Exercise browser TURNS separately over the broker with a complete trusted chain, wrong hostname and missing intermediate carrying a loopback AIA URL. Require the valid connection and nonce, explicit rejection of the two invalid cases and zero AIA requests. Record revocation behavior separately.
- For the browser TURNS control, bind one test DER anchor and the exact synthetic TURN host and port to the signed Dev candidate and profile B's mandatory proxy session before page creation. Use the session-creation IPC so a Networking restart carries the same scope. Admit the scope only in the private runtime build and after verifying the Dev host identity from the kernel-provided audit token. The HTTPS navigation test anchor applies to a different trust callback. The [private TURN/TLS anchor patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-turn-tls-qa-anchor.patch) adds the default-off CMake option `NEANTIK_TURNS_QA_ANCHOR`. The signed Dev host reads `NeAntikQATURNSTrustScope` with one synthetic profile UUID, port and DER anchor. The Networking process checks the launch XPC peer audit token against the existing Developer ID requirement before entering its sandbox. Apply the [peer authentication follow-up patch](../Experiments/OwnedWebKitNetworkBoundary/source-ports/db6a98765e/neantik-webkit-turn-tls-presandbox-peer.patch) after the detached click patch. Session creation consumes that authenticated result. Serve the wrong-host certificate at the same configured TURN address so the negative test exercises the scoped verification callback. Start the loopback controller with `--rtc-relay-policy --turn-tls-material <owner-only-directory>` containing `chain.pem`, `leaf.key` and `ca.der` at mode 0600. Seal with the successor packager, then bind the resulting receipt and ZIP digest through the running controller. The controller verifies the ZIP before the launcher can consume it. Use `--turn-tls-certificate-case complete|wrong-host|missing-intermediate` in place of supplied material to generate a fresh chain and an instrumented loopback issuer. The controller counts requests after a successful independent fetch. For the negative cases, the final receipt requires an explicit certificate alert from the client for every broker connection, zero completed handshakes and allocations, and zero additional issuer requests. A browser timeout only records that it received no relay candidate. Production artifacts must exclude the TURNS test scope and its setter.

Run one native build or candidate at a time. Use two build jobs when resource admission allows them and resume the same graph with one job after memory pressure. Gate launches on resource admission. After two identical failures, diagnose the failure boundary before retrying. Keep original inputs, received fixtures, publication and rollback intact.

### Owned WebKit window and input boundary

On macOS 27.2, the AppKit event loop can load system WebKit into the owned host through the system text-input stack. A detached WKWebView with the cursor-accessory guard can navigate and render a software snapshot with a single owned image. Qualify a separate presenter before changing the product host:

1. Keep the owned renderer, profile store, lease and broker in the attested process. Put the window and input handling in an AppKit presenter whose dependency closure excludes owned WebKit. The presenter receives frames and sends typed input. It has no profile store, upstream credentials or route activation authority.
2. Prove one bounded frame handoff. Measure successful display from the presenter's native window, process identity on both sides, and renderer image identity after delivery. The macOS WKWebView snapshot path excludes accelerated content such as video and WebGL. Use it for this experiment only. Qualify accelerated frame transfer, pacing, resize and device scale before integrating the window path.
3. Feed a click and text captured by the presenter's responder into the engine's native event dispatch. Check trusted pointer and keyboard events, edited value and the resulting frame using a synthetic document. Keep page scripts as observers in this test. Qualify text composition, scroll, focus, keyboard commands and accessibility before calling the split window usable.
4. Bind presenter messages to the existing host generation. Keep frame data off the small lifecycle control channel, bound dimensions and queued work, and reject stale generations. Close the entire owned session on presenter or renderer loss. Verify no stale frame or input survives profile A → B → A, both processes exit, and the normal lease and route revocation complete.

Use the manager as the native presenter. The local subprocess check verified that two anonymous Unix stream sockets attached to the child's standard input and output can carry frames and input in the reverse directions while the original control exchanges continue. Adopt this only for the presentation path, with an explicit anonymous socket validator and separate reader/writer ownership. Keep graceful save acknowledgements on the control direction even when frame writes are backpressured. Qualify frame transfer and pacing separately, including how accelerated buffers are shared.

The [IOSurface transport control](../Experiments/OwnedWebKitNetworkBoundary/iosurface-xpc/run.sh) transfers two known BGRA buffers from a separate native XPC process and checks the peer PID, generation, sequence, layout and pixels. The same control with the signed owned Frameworks path renders two actual WebGL frames in a separate XPC service, imports each IOSurface into Metal in the consumer and verifies the exact pixels. The WebKit service uses an NSRunLoop on its main thread. This validates accelerated transfer through a standalone harness. Integrate that transfer with one renderer per profile and present both frames in the manager. Bind the connection to the launched renderer and active generation. Acknowledge each frame after the manager GPU finishes reading it and bound the number of in-flight frames.

The [direct-child Metal transport control](../Experiments/OwnedWebKitNetworkBoundary/shared-metal-frame/run.sh) uses an unlinked POSIX shared memory region and the existing direct-spawn shape. It delivers actual WebGL frames from a detached renderer linked to the signed owned runtime. The renderer uses Metal to copy from the compositing surface into shared memory. The consumer maps read-only, verifies the pixels after a GPU copy, acknowledges, and reaps the direct child. Prefer this path for the current process model. The XPC control remains useful for the alternative topology where an application owns a bundled XPC renderer.

The signed private QA mode `--qa-metal-frames` transfers a bounded shared region and a dedicated frame socket after both sides attest the existing host and acknowledge the profile bootstrap. The host reuses one compositor, texture and shared buffer at up to 12 frames per second. The manager imports the buffer read-only, blits into the Metal window, acknowledges after GPU completion and records presentation only after the drawable is presented. Candidate, fixture plan and signed host must agree on the mode. The manager interrupts the frame socket when the window closes. With `--click-probe`, the host advertises a single click for the exact signed synthetic HTTPS origin and original navigation. The manager arms the window after sampling a red swatch from a presented buffer. The child checks the active view and navigation before dispatching the click. Phase A1 requires a trusted origin event and same-generation evidence of a later presented green swatch. Apply the five-phase network sequence and close/reopen checks to the same candidate. The development presenter resizes its fitted content rectangle with the window while keeping the renderer viewport and shared buffer fixed. General pointer and keyboard input, renderer resize and backing scale changes require their own qualification.

Use the detached session to check proxy and WebRTC while the presentation path is being completed. The headed acceptance still requires startup and input without weakening image attestation. Keep Chromium and system-WebKit Direct gates scoped to their existing launch paths.
