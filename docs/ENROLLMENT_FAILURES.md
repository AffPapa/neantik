# Ошибки подготовки ключа проверки выпуска

Изменение находится в разработке после 0.8.24. Оно касается служебного ключа
проверки кандидата, а не ключей, паролей или данных пользовательских профилей.

Раньше отказ чтения после успешного резервирования оставлял служебную запись.
Вызывающий код получал владение только после завершения создания ключа и не
мог убрать этот промежуточный результат. Два новых теста воспроизвели четыре
нарушения на прежнем коде.

Теперь очистка зависит от фактически завершённого этапа:

| Отказ | Действие |
|---|---|
| Резервирование отказало, в том числе из-за параллельного сеанса | Ничего не удаляется: эта попытка ничего не приобрела. |
| Проверка существующего ключа отказала или нашла прежний ключ | Освобождается собственная служебная запись; прежний ключ сохраняется. |
| Backend подтвердил, что ключ ещё не создавался | Освобождается служебная запись. |
| Экспорт или полная проверка P-256 после создания отказали | Native backend удаляет только полученную ссылку `SecKey`; запись освобождается после подтверждённого удаления. |
| Результат создания или удаления неизвестен | Запись сохраняется как запрет повторного использования; успешная очистка не заявляется. |
| Самопроверка или запись результата отказала после успешного enrollment | Удаление ключа предшествует освобождению записи; ошибка очистки возвращается явно. |
| Выходной файл уже зафиксирован | Файл и его ключ сохраняются. |

В журнал возвращаются этап, закрытая категория исходной ошибки, состояние
очистки и её отдельная ошибка. Произвольные описания backend-ошибок, данные
ключа и пути туда не копируются. Ошибка без известной категории обозначается
`unclassified`.

Native создание, вернувшее ошибку без ссылки `SecKey`, считается неопределённым.
Код не удаляет предполагаемый ключ по его tag. Автоматического повтора,
пересоздания authority или очистки старых неизвестных записей нет.

Проверки используют P-256 в памяти и временные выходные файлы. Они охватывают
владение, отказ, сохранность соседнего сеанса, параллельный дубликат и результат
после фиксации файла. Это не проверка реального Keychain, Secure Enclave,
аварийного выключения или подписанного кандидата. Нативная квалификация этой
новой ветки остаётся отдельным gate следующего кандидата; ранее опубликованная
0.8.24 не меняется.

Обычная конкурентная подготовка защищена атомарным резервированием. Защита от
произвольного внешнего удаления и замены записей Keychain этим изменением не
доказывается. Историческая незавершённая попытка 18 октября не очищалась и не
объявляется восстановленной задним числом.

## Результаты проверки исходников

[Машиночитаемый отчёт](evidence/enrollment-failure-development.json): 45 связанных
Swift-тестов прошли; полный Python-прогон — 1734 теста, 19 пропусков. Полный
Swift-прогон сохранил один отказ фикстуры MCP среди 1695 зарегистрированных
тестов. После исправления генерации тестовых данных отдельный набор MCP прошёл
11 тестов, включая отказ на намеренно повторённом seed. Причина конкретного
старого случайного набора не восстановлена; исходный отказ не скрывается.
