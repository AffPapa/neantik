# Отчёт между версиями

Пункт44 плана1.0. Инструмент сравнивает публичные release records и создаёт
JSON и читаемую сводку. Он не запускает браузер, не проверяет подпись измерений
и не объявляет новую версию готовой.

Готовый пример: [0.8.11 → 0.8.12](evidence/regression-0.8.11-0.8.12.md),
[JSON](evidence/regression-0.8.11-0.8.12.json).

```bash
python3 -B scripts/compare-release-reports.py --before 0.8.11 --after 0.8.12
python3 -B scripts/compare-release-reports.py --before 0.8.11 --after 0.8.12 --format markdown
python3 -B scripts/compare-release-reports.py --before 0.8.11 --after 0.8.12 --verify-snapshot
```

## Что сравнивается

- Версия, уникальный build, source commit и отдельный commit сборки менеджера.
- SHA-256 менеджера и двух исполняемых файлов runtime. Совпадение этих файлов
  не является сравнением всего инвентаря или доказательством поведения API.
- Заявленные результаты локальной/скачанной сборки, обновления, отката,
  notarization, Gatekeeper, MCP и сайта. Неизвестное остаётся неизвестным;
  текст с `OPEN`, ошибкой или незавершённой доставкой не превращается в PASS
  из-за встретившегося позже слова PASS.
- Исходные test summaries вместе со skips/ошибками и ограничениями. Число
  reported-тестов не объявляется числом успешно исполненных тестов.
- Изменения из соответствующих публичных release notes и хеши исходных записей.

## Сопоставимость измерений

Опциональное `measurementContext` в release record должно содержать
`osVersion`, `architecture`, `headed`, `memoryPressure`, `thermalState`,
`environmentSHA256`, `harnessSHA256`, `fixtureSHA256` и
`profileConfigurationSHA256`. Типы и значения проверяются; все условия должны
совпасть. Environment digest описывает условия собственного тестового стенда,
без serial/личных IP/ICE/полного fingerprint пользователя. Конфигурация и
fixture также относятся только к синтетическим профилям.

Совпадение таких деклараций не подтверждает подлинность измерений. Перед
сравнением поведения нужны связанные authenticated exact-candidate reports,
реальные операции и контроли; перед численным сравнением скорости — одинаковая
методика и условия. Эти результаты инструмент не выдумывает: сейчас
`behaviorRegressionVerdict=not_established`, `performanceComparison=not_measured`.

В записях0.8.11/0.8.12 полного контекста нет. Сводка честно показывает эту
границу, открытые hosted-headed/site gates0.8.12 и сохранённые исходные ошибки.
Это реализация отчётного инструмента; полная поведенческая приёмка пункта44
на сопоставимых условиях остаётся открытой.

## Обновление отчёта

После изменения release records/notes заново создать оба файла примера.
Тест сравнивает сохранённые JSON/Markdown со свежими результатами из источников:
устаревший snapshot и выдуманное «регрессий нет» отличаются и требуют исправления.
Новый бинарный выпуск, сборка Chromium и нотарификация для обновления сводки
не нужны. Immutable assets и исторические подписи не изменяются.
