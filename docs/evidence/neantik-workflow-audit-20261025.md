## Short release sequence

1. Resolve applicability against the canonical exact-byte worksheet; start with the four linked-image rows and group the 78 already-mapped resources by source/license. Complete the matching source/build offer once. If applicability cannot be responsibly resolved internally, use one qualified review or a product/supply-chain choice that removes the unresolved redistribution; do not mark unknown rows PASS.
2. Include the manager launch-cancellation fix in source. Freeze one production candidate only after notices/source inputs are final. Freeze one correctly fixture-bound Dev QA archive only if a new owned-runtime smoke is still needed.
3. Before Apple submission, verify one archive against the exact smoke harness: embedded fixture root, bundle/profile identity, manager/host/runtime inventory, pin, notices, signature, Gatekeeper, and the launcher receipt. Submit once.
4. Run the manager's live admission and one bounded headed test on that exact accepted archive. Reuse already-passed Chromium, build, source, and route evidence where bytes/harness/scope still match.
5. Build/sign/notarize/staple the one production ZIP/DMG; verify downloaded bytes; publish matching GitHub assets and browser.free metadata; confirm live hashes and links. Never update affpapa.org.

## No-repeat rule for this workstream

Before any retry, record the exact changed input and the gate it invalidates. If neither changed, reuse the receipt. After two identical failures, stop retries and diagnose the failed boundary. A successful build, Apple acceptance, or manager window is not a PASS for owned-WebKit launch, proxy/no-Direct, source compliance, or public delivery unless that exact gate was observed.
