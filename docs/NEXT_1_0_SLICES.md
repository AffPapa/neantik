**Этап QA6:** production запуск с прокси
по-прежнему запрещён. QA6 принята Apple, билет прикреплён; замена выключенной

конкретное расхождение подписи/identity ещё не установлено.

Свой фильтр удалён/readback, QA6 выключена, свои процессы и endpoints завершены;
штатное меню Quit работает. Старая QA5 остаётся неактивной записью удаления
до будущей пользовательской перезагрузки; она не требует нового repair.

не совпадают. Конкретная гостевая identity не читалась; заменять владельца
общим Apple helper нельзя. Свой фильтр удалён, QA7 выключена, шесть процессов

проверяющий код: 7 условий совпадают, неправильные ID/hash отклоняются. Изучен

установленному системному бинарнику ещё не доказано. [Выводы и отвергнутые

Отдельная подписанная исследовательская копия прошла четыре headed-режима:
без политики и политика A → B → повторно открытый A. Проверены восемь
контекстов с рисованием, по42 шрифтовых и42 generic-операции в каждом.
В AudioWorklet шрифтовых API закономерно нет; проверено реальное выполнение
процессора. Создание и уничтожение всех девяти контекстов подтверждены
независимо; попытка объявить ещё живые контексты завершёнными отклонена.

Обнаружена исходная особенность Chromium: SharedWorker/ServiceWorker получают
пустые generic-настройки, поэтому их monospace fallback отличается от страницы.
Новая четырёхфайловая дельта заполняет только пустые семь COMMON defaults при
явной политике system-v1. Пересобраны два C++-объекта за188секунд; предыдущие
runtime сохранены. В настроенных режимах согласованность прошла; исходное
расхождение без политики сохранено как чувствительный отрицательный контроль.
Это не полная передача локализованных/пользовательских настроек шрифтов.

[Результат и ограничения](evidence/font-nine-context-development.json):
по2954 строгих парных проверки в каждом настроенном режиме, отдельно по294
generic-сравнения,1512 A→B→A проверок; четыре exit0, нормальные ресурсы,
очистка тестовых данных и неизменность полного runtime. Ошибки модели стенда
(CSS serialization, remote frame tree, document.write и URL AudioWorklet)
сохранены с причинами и отдельными отрицательными контролями.

Font Access, дополнительные styles/collections, manager opt-in и точный
release candidate остаются открыты. Эта политика ещё не включена в поставку.


## Разработка: Font Access и отзыв разрешения

На той же подписанной исследовательской копии прошли пять headed-режимов:
native, seed без политики и policy A→B→A. Запрос ограничен тремя заранее
известными именами и одним заведомо отсутствующим. При granted native выдаёт
оба собственных шрифта и системный контроль; system-v1 — только контроль.
Полный пользовательский список шрифтов в отчёт не передаётся.

Проверены реальные denied→granted→denied события и запросы. После отзыва
новый запрос пуст; сохранённый FontData продолжает отдавать тот же blob —
это поведение Chromium. Полученные blobs действительно загружены в FontFace
и отрисованы; для собственных шрифтов проверены пять стабильных таблиц,
для системного — структура и известное имя без вывода байтов или их хешей.

Контроль разрешений исправлен по исходникам: iframe с явным allow законно
получает делегированное разрешение верхней страницы. Самостоятельная видимая
страница B в том же BrowserContext разрешение A не наследует; фактический
запрос без жеста отклонён. Scope CDP здесь — top-level A, не изоляция каждой
пары embedded origins. Исходный ошибочный FAIL сохранён отдельно.

[Доказательства](evidence/font-access-development.json):273 поведенческие
проверки,18 blob-операций,35 native ACK, пять exit0, normal admission,
очистка и неизменность runtime. Font Access этого среза больше не открыт;
системный диалог, дополнительные collection/variation условия и квалификация
поставляемого кандидата остаются отдельными gates. Новая сборка не запускалась.


## Следующий P0: variable-font provenance

Реальная Skia-проба выявила ложный отказ: проверенный системный UI-шрифт
принимался, его клоны с другим весом — нет. Исправлен отдельный source-layer:

## Политика шрифтов подключена к менеджеру — проверена в Dev

В редакторе Chromium-профиля появился переключатель «Только системные шрифты Mac».
Он включается только с точно проверенным подписанным runtime. Legacy-профили
сохраняют прежний режим; WebKit эту Chromium-политику не принимает. MCP читает
и меняет `fontPolicy` через обычные revision/stopped ограничения. Значение
`system-v1` — запрос настройки, а не доказательство её применения в сеансе.

На отдельном Dev-стенде MCP трижды открыл один профиль: native → system-v1 → native.
Проверены фактические аргументы mock Keychain и две разрешённые переменные
дочернего браузера, неизменность identity/seed, сохранение LocalStorage и штатное
завершение без leases. В настоящем редакторе проверены сохранение, отмена и
повторное открытие включённого/выключенного режима.

99 целевых Swift-тестов прошли. Общий прогон завершился с23 ошибками sandbox
в7 группах сокетов/своих процессов; он не записан как полностью успешный.
Эти группы и финальные font/MCP-контракты отдельно прошли в подходящей среде:
85 тестов в11 группах. Python:1513 тестов,19 пропусков.
[Точные границы результата](evidence/font-manager-activation-development.json).
Далее — точный подписанный поставляемый кандидат и Direct gates. Опубликованные
архивы не заменялись; готовность1.0 этим срезом не объявляется.

## Font runtime: подключение к упаковке

Release-селекторы различают прежний M156 и `font-system-v1`. Закрытый список
копирования включает публичные документы предка, шесть font-слоёв, собственные
QA-исходники и публичный отчёт headed-проверки. Старые документы и updater pins
сохранены. Генератор отчёта и отдельный packaged verifier сверяют весь новый
подписанный runtime: старый runtime с новыми метками отклоняется.

Перед исполнением генератора лицензий отдельно проверяются9552 актуальных
signing/license/import/metadata файла; одна группа native COPY проверяется
с точными aliases и числом hardlinks. Это ограниченная проверка входов
упаковки, а не повтор полного source-аудита или разрешение пересборки.

Python-контроли проверяют настоящую копию evidence, повреждение и symlink,
разделение старого/нового source proof, контракт в candidate manifest и notices.
Один тестовый путь macOS исправлен с `/var` на канонический путь; исходный
неуспешный прогон сохранён.

## Font runtime: evidence и updater зафиксированы

Новый runtime, evidence и исходный отчёт проверки связаны отдельной compiled
политикой. Прежняя политика сохранена: принимается только целиком прежний или
целиком новый набор. Смешанные runtime/evidence/report, изменённые размеры,
Mach-O и поля provenance отклоняются. Bootstrap передаёт измеренный digest.
Упаковка сохраняет дату исходного отчёта; новый timestamp не создаёт новую
проверку. Права файлов evidence не зависят от umask, историческая security
baseline хранится отдельно от текущей baseline публикации.

Полные source-прогоны: Swift —1635 тестов/194 suites,71 пропущен;
Python —1539 тестов,19 пропущено. Пропуски не засчитаны как нативный PASS.
Нативное enrollment и точный signed/headed кандидат затем квалифицированы
в выпуске 0.8.18. Updater129 новый runtime автоматически не принимает;
переход выполняется через подписанный DMG/ZIP, без обещания совместимого
автоматического обновления.

На отдельных QA-копиях проверены настоящая установка с ACK и rollback при
ошибке перед ACK. Проверены обе копии приложения и журнал решения; ProfileStore
и production Keychain не открывались. Нативный тест обнаружил чтение старого
пути после transfer в DEBUG owner; исправление читает runtime под custody
перемещённого slot. После исправления оба сценария прошли, как и22 связанных
unit-теста (3 пропуска). [Границы результата](evidence/font-updater-native-development.json).
Это не квалификация production feed или автоматического перехода129→130.
Точная поставка нового кандидата завершена в [0.8.18](../releases/v0.8.18.json).
Полные network/Canvas/WebGL/Audio матрицы на successor заново не выполнялись;
старые результаты сохраняют исходные привязки. Это не закрытие всей 1.0.
