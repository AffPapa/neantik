# Что остаётся до 1.0

База: опубликованная [0.8.16 (128)](../releases/v0.8.16.json).
Это public alpha, а не завершённая 1.0. Сохранённые проверки применяются к
указанным в них входам; список ниже не является заданием повторить их все.
Полная 45-пунктная приёмка остаётся в [major-плане](MAJOR_1_0_PLAN.md).

## Закрыто в 0.8.14–0.8.15

Автосохранение вкладок WebKit опубликовано. Четыре реальных оконных сценария
прошли без пропусков; на точном подписанном кандидате подтверждены запись до
закрытия окна, History API, порядок/выбор вкладок, удаление закрытой вкладки из
файла и штатный выход. Недостающий signed-контроль B завершён на 0.8.15:
режим «Стартовая страница» не пишет session-файл и после повторного открытия
возвращает исходный URL. Первый запуск при warning был отклонён; попытка
состоялась только после нового normal observation. Это не полный backup
и не завершение пункта 36 для всех отказов.

В 0.8.15 исправлена привязка подтверждения recovery к профилю и конкретному
журналу. Реальные файловые wrong-profile/stale-stage контроли сохраняют данные;
Dev-окно при неподтверждённом журнале скрывает опасные действия и объясняет
следующий шаг. Формат backup и identity не менялись.

## Закрыто в0.8.16

Удаление закрытого профиля WebKit выполняется public UUID API macOS. Долговечный журнал блокирует повторный запуск удаляемого профиля и позволяет явно завершить прерванную операцию после перезапуска. До native dispatch профиль исключается из обоих metadata snapshots; неожиданные локальные файлы сохраняются, а не удаляются рекурсивно.

Финальный source-native A/B путь, точные signed GUI удаление/сохранность/recovery, headed Chromium, doctor13, Apple ZIP/DMG, публичные байты, downloaded MCP18/7 и browser.free153 проверены. Первый downloaded MCP запуск остановлен до процесса при warning; фактическая попытка произошла при normal после завершения собственных verifier процессов. Повторных сборок не было. [Результат и ограничения](../releases/v0.8.16.json).

## Выполнено в исходных инструментах после 0.8.14 (45)

После выпуска устранены подтверждённые причины лишней работы: Python-потомки
тестов не создают executable cache в исходниках; анонимный downloader игнорирует
curlrc, proxy credentials и TLS-переменные оператора, ошибки не возвращают сырые
stderr. Реальные curl/Python controls проверены. CI ловит устаревшую вводную
ссылку README и fine-grained GitHub tokens без вывода их значений. Это изменения
служебных скриптов, не новая функция браузера и не основание пересобирать Chromium.

Сетевой инвентарь сверён с фактическим fetcher обновлений и browser-route
диагностикой. Наличие harness или исправленной документации само по себе
не закрывает DNS gate.

Первый producer теперь реализован: собственные UDP DNS и HTTPS DNS endpoints,
отказы resolver/upstream, восстановление, контролируемый Direct-обход,
ограниченный pipe-CDP runner и отдельный анализатор сохранённых результатов.
Реальные локальные сетевые и отрицательные controls прошли. После первоначального
отказа до запуска выполнены3headed-сессии signed runtime126 (те же runtime-байты
поставляются в127), все при normal1/thermal0. Стандартный анализатор подтвердил
8наблюдений и очистку собственных процессов. DoH использовал собственный
сертификат с точечным тестовым SPKI; это не проверка обычного доверия HTTPS-upstream.
Следующий срез — manager/relay integration; глобальные DNS/UDP и все19–22
остаются открытыми. Описание — в [Network Reality Harness](NETWORK_REALITY_HARNESS.md).

Manager DNS producer и custody проверены на скачанной128 после normal admission.
Первый анализ отклонён из-за неверной модели preflight commit и повторных
запросов Chromium во время отказа. Исходные FAIL и receipts сохранены;
строгое offline-восстановление metadata и отрицательные контроли исправили
анализ без нового запуска. [Результат](evidence/manager-dns-0.8.16.json)
не означает полную сетевую квалификацию1.0 и не меняет опубликованные байты128.
