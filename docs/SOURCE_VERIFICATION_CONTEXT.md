# Повторное использование проверки исходников

`verify-packaged-runtime-report.py` проверяет исходные доказательства M156
один раз за вызов. Из них он получает ожидаемые поля отчёта и список файлов
evidence. Затем отдельно сверяет каждую копию evidence, поля её отчёта и
фактический runtime. Результаты этих трёх проверок не кэшируются.

## Когда это работает

- Проверяющий код выполняется из полного чистого Git checkout.
- Снимок охватывает все tracked-файлы, их байты, identity и родительские каталоги.
- Загруженные собственные Python-модули принадлежат этому checkout.
- Интерпретатор, import path, рабочий каталог и окружение не меняются.

До и после каждой операции эти условия проверяются заново. Контекст существует
только в памяти одного процесса: его нельзя загрузить из JSON или передать
следующему запуску. Значения переменных окружения не пишутся в отчёты.

Для dirty, вложенного или отдельного checkout сохраняется прежняя полная
проверка без контекста. Ошибка в доказательствах, подмена собственного модуля
или изменение уже зафиксированных входов — отказ, а не повод переключиться
на менее строгую проверку. Ошибка или прерывание операции навсегда делает
данный контекст непригодным.

## Что проверяется у каждой копии

- Её lock читается до и после проверки.
- Каждый ожидаемый файл читается заново; байты сравниваются с исходником.
- Чтение ограничено по размеру, запрещает symlink и проверяет FD/path identity.
- Полный namespace proof/font/security/component проверяется на лишние,
  связанные и специальные файлы, включая вложенные каталоги.
- Поля отчёта сверяются с ожидаемыми; исправный source не оправдывает
  подменённый отчёт.
- Дерево реального runtime измеряется заново и сравнивается с прежним
  подписанным runtime proof.

Повторный JSON/semantic разбор одинаковых proof-файлов заменён сравнением
байтов и свежей проверкой namespace. Проверка подписи, notarization,
Gatekeeper, ZIP/DMG и публичных скачанных байтов выполняется отдельно.
Контекст не доказывает работоспособность браузера и не заменяет headed QA.

## Проверка изменения

Контроли находятся в `scripts/tests/test_chromium_15612_source_context.py`:
два назначения, повреждение/удаление/замена файла, лишние члены namespace,
изменение lock/source/interpreter/environment, чужие модули и прерывание.
Отдельные routing-тесты сохраняют обязательность фактического runtime closure.
Реальная source-only интеграция измеряется на сохранённом выпуске; она не
запускает браузер и не является новой квалификацией этого выпуска.

Четыре явно перечисленных checker-файла имеют ограниченный набор проверок
в `plan-manager-checks.py`. Неизвестный соседний workflow-файл по-прежнему
выбирает полную регрессию. Вывод planner имеет статус `not-run`.

Ограничение: это устранение повторов внутри одного Python-вызова. Разные
вызовы Direct pipeline продолжают проверять исходники независимо; ускорение
всей публикации нельзя приравнивать к ускорению этого участка.

## Измеренный результат

На сохранённом downloaded 0.8.23 (135) старый путь занял 32,375 с, новый —
9,517 с, включая создание контекста. Полных вызовов source entry стало один
вместо трёх. Обе цепочки сверили реальные evidence/report/runtime; ложное
поле отчёта и повторное использование после отказа были отклонены.
[Машиночитаемый scope и результаты](evidence/source-verification-context.json).

Это один последовательный замер old → new: кеши ОС и нагрузка могли повлиять
на время. Общая Direct-транзакция и её отдельные Python-процессы здесь не
замерялись; ускорение всего выпуска пока не установлено.
