# Профили WebKit — экспериментальный режим

NeAntik может открыть профиль в собственном окне на системном WebKit — движке Safari. Это окно NeAntik с отдельными данными сайтов. В0.8.3 доступны вкладки и отдельные данные каждого профиля. На точном подписанном кандидате проверены изоляция и сохранение после полного перезапуска; ограничения ниже остаются в силе.

## Как создать профиль

1. Нажми «Создать профиль…».
2. Выбери «WebKit · движок Safari» и задай имя.
3. В «Запуск и оформление» укажи стартовую страницу. Можно использовать `about:blank`. Для сохранения адресов, порядка и выбранной вкладки после штатного выхода выбери «Предыдущие вкладки».
4. Сохрани и нажми «Запустить».

Адресная строка: ⌘L, открыть адрес: Return, обновить: ⌘R, назад/вперёд: ⌘[ / ⌘], закрыть: ⌘W. При выходе из NeAntik его окна WebKit закрываются. После повторного запуска сохранённый профиль использует то же хранилище.

## Что сохраняется и разделяется

Каждый профиль использует постоянный `WKWebsiteDataStore(forIdentifier:)` со своим UUID. Cookies, LocalStorage и IndexedDB проверены на двух профилях одного origin, после закрытия окна и штатного выхода из приложения. Копирование настроек и импорт создают новый UUID и пустые данные сайтов. Переименование сохраняет UUID. Эти проверки не доказывают сохранение последней записи при аварийном отключении питания.

Старые профили остаются Chromium. Менять движок существующего профиля нельзя. Набор с WebKit записывается в schema 2, которую старый менеджер должен отклонить; не открывай такие данные старой версией. Export настроек сохраняет движок, но не переносит данные сайтов. Библиотека с WebKit-шаблонами также использует schema 2; старый менеджер должен её отклонить.

## Границы первой версии

- Устройство, WebKit и его web APIs предоставляет macOS. Fingerprint-политика Chromium не переносится на WebKit; отдельный seed не создаёт изменённый WebKit-отпечаток.
- Поддерживаются HTTP, HTTPS и `about:blank`. Вкладки: ⌘T — новая, ⌘W — закрыть текущую, ⌘⇧[ / ⌘⇧] — переключить. Данные вкладок одного профиля общие. До 32 вкладок; всплывающие окна без действия пользователя заблокированы. Место сохранения загрузки выбираете вы, прогресс и отмена — в списке профиля. Готовый файл можно показать в Finder. Существующие файлы не перезаписываются; закрытие отменяет активные загрузки. Автоматического продолжения после сбоя нет. Режим «Предыдущие вкладки» сохраняет полные HTTP(S) адреса с query/fragment в приватном файле профиля. Специальные адреса восстанавливаются как пустые вкладки; формы, история переходов и последние несохранённые изменения при аварии не обещаются.
- Прокси WebKit пока запрещён: профиль с настроенным прокси не запускается. Прямое подключение вместо заданного прокси не выполняется. Измерения DNS/WebRTC/маршрута Chromium не относятся к WebKit.
- Расширения Chromium и полный BrowserData backup не применяются к WebKit. Удаление WebKit пока недоступно; профиль можно архивировать. С0.8.8 есть отдельная очистка HTTP-кэша WebKit: только у закрытого профиля, без измерения размера, CodeCache или recovery journal Chromium. Она сохраняет входы, данные сайтов и список вкладок; временная очистка CacheStorage сюда не входит.
- MCP может создавать, редактировать, искать и копировать настройки WebKit-профилей. Запуск из stdio явно отклоняется: собственное окно требует GUI NeAntik. GUI IPC ещё не реализован.
- Для отдельных профилей используются процессный и metadata guards. Настройки открытого WebKit-профиля защищены от второго менеджера. Системные разрешения камеры/микрофона и внешние сайты не квалифицированы этим стендом.

## Воспроизведение проверок

Запусти `python3 scripts/run-webkit-fixture.py --port 8765`. Это собственный стенд только на loopback, без журналов запросов. В новом Dev fixture создай два WebKit-профиля со страницей `http://127.0.0.1:8765/fixture`. В A запиши A; B должен быть пустым. В B запиши B. Закрой NeAntik и открой снова: чтение должно вернуть A и B отдельно.

Live тесты `WebKitProfileTests` требуют `NEANTIK_WEBKIT_LIVE=1` и `NEANTIK_WEBKIT_FIXTURE_URL=http://127.0.0.1:8765/fixture`. Без этих флагов live-кейсы отмечаются как skipped. В тестах есть намеренно общий store как отрицательный контроль изоляции, запрет прокси/неподдерживаемого URL, schema downgrade, двойной запуск и освобождение store. Используй проектный developer-dir resolver и jobs=2. Не запускай вторую нативную сборку.

Первичная GUI/runtime проверка выполнена на macOS 27 ARM64. API доступны с macOS 14, но фактический запуск на macOS 14 здесь не проверен. Ad-hoc Dev.app не заменяет signing/notarization/Gatekeeper gates подписанного релиза.
